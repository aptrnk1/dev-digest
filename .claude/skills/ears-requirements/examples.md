# EARS — погано → добре (DevDigest)

## Розмите слово
- ✗ «Список конвенцій має швидко завантажуватися.»
- ✓ **NFR1** Латентність: `GET /repos/:id/conventions` для ≤ 20 кандидатів
  відповідає ≤ 300 мс p95 на seed-даних — перевірка: `[it]` з таймером.

## Дві поведінки в одному AC
- ✗ «КОЛИ юзер натискає Accept, система зберігає статус і показує Undo.»
- ✓ **AC3** (event, US2) КОЛИ юзер натискає Accept на картці, API повинен
  (shall) зберегти `status = accepted`. `[it]`
- ✓ **AC4** (event, US2) КОЛИ API підтвердив Accept, UI повинен (shall)
  показати на картці бейдж «Accepted» і кнопку Undo. `[unit]`

## Немає unwanted-пари
- ✗ лише «КОЛИ юзер запускає extraction, API повинен (shall) повернути 202.»
- ✓ + **AC6** (unwanted, US1) ЯКЩО для репо немає клону, ТОДІ API повинен
  (shall) повернути 409 `repo_not_indexed`, а UI — показати пояснення з
  посиланням на індексацію. `[unit]`

## Опис коду замість поведінки
- ✗ «`ConventionService.extract()` викликає `repoIntel.getSamples()`.»
- ✓ **AC2** (ubiquitous, US1) Система повинна (shall) відбирати для аналізу
  лише конфіги з кореня клону та ≤ 12 найрелевантніших source-файлів. `[unit]`

## Стан
- ✓ **AC7** (state, US1) ПОКИ скан має статус `running`, UI повинен (shall)
  показувати прогрес і блокувати кнопку Re-scan з підказкою «Scan in progress».
  `[unit]` `[e2e]`

## Опція
- ✓ **AC9** (optional, US3) ДЕ для агента ввімкнено скіл `convention`, система
  повинна (shall) додавати тіло скіла до системного промпту агента. `[unit]`

## Комбінація
- ✓ **AC10** (complex, US1) ПОКИ скан `running` довше 10 хв, КОЛИ надходить
  новий запит extraction, API повинен (shall) позначити старий скан `failed`
  і прийняти новий запит з 202. `[it]`

## LLM-залежна поведінка
- ✗ «e2e: модель знаходить 3 конвенції.»
- ✓ **AC5** (unwanted, US1) ЯКЩО цитату кандидата не знайдено в `line ± 3`,
  ТОДІ система повинна (shall) відкинути кандидата. `[unit]` з мок-провайдером.
