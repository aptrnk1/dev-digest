# Spec: Smart Diff

Статус: Draft · 2026-10-21 · пакети: `server`, `client`, `e2e` (+ seed)

## 1. Context
Вкладка **Files changed** (`DiffTab` → `DiffViewer`) показує файли в порядку
GitHub: lock-файл поруч із бізнес-логікою. Знахідки агентів живуть окремо на
вкладці **Agent runs** (`FindingsTab` → `FindingCard`), тож щоб зіставити
знахідку з кодом, треба стрибати між вкладками.

Каркас уже є, але не використовується: контракти `SmartDiff*`
(обидві копії `vendor/shared/contracts/brief.ts:109-142`, `SmartDiffResponse` у
`review-api.ts:80-82`), i18n `prReview.json → smartDiff`, хелпер
`repoIntel.getFileRank(repoId, paths)` (percentile з `file_rank`).

Мета: (1) детерміновано (без LLM) класифікувати файли PR за роллю і показати їх
групами у фіксованому порядку; (2) накласти знахідки рев'ю на diff — лічильник
на групі, індикатор на картці файла, коментар під рядком.

## 2. User stories
- Як рецензент, на **Files changed** я бачу файли згрупованими:
  **Core → Tests → Wiring → Docs → Boilerplate**; порожні групи не показуються.
- Як рецензент, на заголовку групи я бачу кількість файлів і скільки з них мають
  знахідки («Core · 4 files · 2 with findings»).
- Як рецензент, на картці файла бачу індикатор знахідок (кількість + колір
  найвищої severity).
- Як рецензент, під рядком коду бачу знахідку тим самим `FindingCard`, що й на
  Agent runs (severity, категорія, rationale, suggestion, accept/dismiss).
- Як рецензент, група Boilerplate згорнута за замовчуванням — lock-файли не
  заважають, але доступні.

## 3. Role classification (сервер, чиста функція, перший збіг перемагає)
Порядок перевірки ≠ порядок показу. Шляхи нормалізуються (`/`, без `./`), матч
регістронезалежний по basename, де це ім'я файла.

`.gitattributes`-оверрайди (`linguist-generated`) — поза scope (§10).

Сортування **всередині групи**: percentile з `getFileRank` desc (файли без рангу —
в кінці), далі `additions+deletions` desc, далі path asc. `getFileRank` повертає
`[]`, коли repo-intel вимкнено — тоді лише вторинні ключі.

## 4. Findings overlay
- **Які знахідки**: з усіх `ReviewRecord` PR беремо для кожного агента лише
  **останній** run (за `created_at`), відкидаємо `dismissed_at != null`.
  Знахідки з `file`, якого немає серед файлів PR, у diff не показуються (лишаються
  на Agent runs).
- **Сервер** рахує для кожного файла `finding_ids` і `finding_lines`
  (`end_line` кожної знахідки) та для групи `files_with_findings` — на цьому
  будуються лічильники.
- **Клієнт** бере самі знахідки з уже завантаженого `usePrReviews(prId)` за
  `finding_ids` (без дублювання payload).
- **Якір рядка**: RIGHT-сторона, рядок `end_line`, якщо він є серед `newNo`
  розпарсеного patch; інакше — найбільший видимий `newNo` у діапазоні
  `[start_line, end_line]`; інакше — **file-level** блок угорі картки
  («Findings outside the visible diff»). Patch відсутній → усі знахідки файла
  file-level.
- Кілька знахідок на рядку — стеком у порядку severity (CRITICAL → SUGGESTION).
- Картка файла зі знахідками **розгортається автоматично** незалежно від
  `AUTO_EXPAND_MAX_LINES`; група Boilerplate згорнута, але якщо в ній є знахідки —
  розгорнута.

## 6. API
`GET /pulls/:id/smart-diff` → `SmartDiffResponse` (zod params + response).
Невідомий PR → 404. Читає збережені `pr_files` (не ходить у GitHub — список файлів
оновлює `GET /pulls/:id`), знахідки — через фасад reviews, ранги — через
`container.repoIntel`. Нічого не пише.

## 7. Server structure (дзеркало Intent Layer)
- Новий модуль `server/src/modules/smart-diff/`: `domain.ts` (чисті
  `classifyFile`, `sortGroup`, `selectFindings`; якір рядка — на клієнті,
  `diff-viewer/findings.ts`, бо лише там є розпарсені `newNo`),
  `ports.ts`, `service.ts`, `compose.ts`, `routes.ts`, `constants.ts`.
- Фасад `container.smartDiff` (lazy getter + `overrides.smartDiff`), реєстрація у
  `modules/index.ts`. Чужі repository не імпортуються — лише через порти/фасади.
- Не копіювати легасі-патерн прямого Drizzle у `pulls/routes.ts`.

## 8. UI (`client`)
- Хук `useSmartDiff(prId)` (ключ `["smart-diff", prId]`), invalidate разом із
  `["reviews", prId]` (run, delete, accept/dismiss).
- `DiffTab` рендерить групи: заголовок групи (лейбл ролі, `N files`,
  `M with findings`, згортання), всередині — існуючий `FileCard`.
- `FileCard`: бейдж знахідок (count + колір `max_severity`), file-level блок,
  передача знахідок у `CodeLine` → під рядком `FindingCard` (той самий, що на
  Agent runs, з accept/dismiss). GitHub-коментарі працюють як раніше.
- Fallback: smart-diff loading/помилка → поточний плаский список у порядку GitHub
  (без overlay), без `ErrorState` на всю вкладку.
- i18n: розширити `prReview.json → smartDiff` (`testsLabel`, `docsLabel`,
  `filesWithFindings`, `findingsOutsideDiff`, `findingsCount`); захардкоджений
  заголовок «Files changed · N files» перенести в i18n. Без `<word>`.
- `import type` лише з `@devdigest/shared`; severity ітерувати з контракту.

## 9. Acceptance criteria
- **AC1** `classifyFile` повертає роль за §3 для кожного рядка таблиці (по
  прикладу на правило) і `core` для решти; barrel без patch → `core`.
- **AC2** `GET /pulls/:id/smart-diff` → групи лише непорожні, у порядку
  core, tests, wiring, docs, boilerplate; 404 для невідомого PR.
- **AC3** Сортування в групі за §3 (percentile → розмір → path); repo-intel
  вимкнено → без падіння.
- **AC4** Знахідки: лише останній run кожного агента, без dismissed, лише файли
  PR; `finding_ids`, `finding_lines`, `max_severity`, `files_with_findings`
  коректні.
- **AC5** Обидві копії контракту ідентичні (`diff`), `contracts.test.ts` зелений.
- **AC6** UI: заголовки груп із лічильниками; Boilerplate згорнута (крім випадку
  зі знахідками); бейдж на картці; картка зі знахідками розгорнута.
- **AC7** Inline: знахідка під рядком `end_line`; поза видимим diff або без patch →
  file-level блок; accept/dismiss з diff оновлює і Agent runs.
- **AC8** Помилка smart-diff → плаский список, вкладка працює.
- **AC9** e2e: на seed-PR видно групи в порядку, лічильник «with findings» і
  inline-знахідку під рядком `src/config.ts:12`.

## 10. Out of scope
- `.gitattributes`/`linguist-*` оверрайди, ручна зміна ролі юзером.
- `pseudocode_summary`, `proposed_splits` (майбутні уроки).
- LLM-класифікація ролей, нова таблиця/кеш.
- Створення нових знахідок з diff, публікація в GitHub.
